# Demo voiceover draft

Every database team has queries that stay correct but become expensive as data,
schemas, and engine releases change. PlanRace turns a reusable query optimization
artifact—not a query answer—into a competitive Bittensor commodity.

The validator publishes the correct query, schema, safe workload distribution,
engine identity, and benchmark policy. This opaque commitment does not reveal the
independently random hidden fixtures. It then sends receiver-bound signed
requests to heterogeneous miners.

Each miner may use any solver, but returns a bounded executable bundle and signs
the response. After the deadline the validator seals submissions and reveals the
committed holdouts. Correctness comes first: the candidate must produce the same
canonical ordered result as the reference on every hidden fixture. A constant or
result-changing answer receives zero before speed matters.

Candidate execution never occurs in the validator process. Disposable workers
enforce read-only SQL, structured index budgets, no network, response limits,
memory and CPU limits, and query deadlines. A timeout or over-budget attacker is
recorded as unavailable; it does not stop the validator.

Only exact and compliant strategies compete on baseline-relative cold and warm
latency, setup and storage cost, and multiple reuse horizons. The closed
multi-family schedule aggregates conservative repeated measurements. Identical
strategies split one portfolio contribution and no strategy exceeds the weight
cap.

Here is the real testnet weight transaction, its finalized extrinsic, and the
metagraph readback. The same signed manifest drives the public dashboard and
verifies from the command line.

Today the evidence is generated workloads, and the production track shown here
must be the actual testnet run—not a simulation. Private customer adapters,
PostgreSQL and DuckDB tracks, and independently operated validators are the next
gates. PlanRace is an open market for continually improved, executable,
validator-verified query plans.
